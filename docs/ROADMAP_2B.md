# C1-2B 路线图：从 125M 验证到 2B 原生类脑模型

> 版本：0.2（2026-08-18）
> 定位：C1（AwareLiquid Cortex）从"实验验证"到"2B 原生模型"的完整路线图。
> 约束：纯类脑架构（砍 attention）——**这是 C1 作为"M3 纯液态激进变体"的探索
> 假设，不是对混合路线的替代**：M1 实测（hybrid 124.80 vs 纯液态 332.99，
> 见 awareliquid/M1）表明注意力是窗口内质量的基础。C1 回答的问题是"如果
> 不要注意力，液态栈能把长上下文+端侧做到什么程度"，M3（私有）回答的才是
> "混合 + 三轴如何逼近 Gemini 3 问答质量"。

---

## 1. 目标与不做什么

**目标**：一个 2B 参数的 C1 原生模型——五层液态认知栈（O(1) 工作记忆 + 稀疏时间尺度路由 + 多尺度预测编码 + 系统1/2 双轨），在长上下文 + 端侧成本上建立可复现的能力基线。

**明确不做**：
- ❌ C1 自身不做 MoE/MLA 等工程扩展——**但 MoE 不是被否定的方向**：M3（混合版）
  的轴1 正是 DeepSeekMoE 配方（细粒度+共享专家，2B 激活/20B 总）。C1 的纯净性
  是为了隔离"液态本身能走多远"的变量，不是对 MoE 路线的否定
- ❌ 不追 AGI 指数（MMLU/GSM8K 打不过同规模 transformer 是预期内，诚实标注）——
  质量对标是 M3 的使命，C1 只认长上下文 + 端侧成本两项指标
- ❌ 不碰 2B 以上的大模型（类脑架构先在小规模证明机制）

**为什么 2B**：
- 端侧（手机/PC/机器人）部署甜蜜点：INT4 下 ~1GB，可进消费级设备
- 类脑架构的计算稀疏性在低规模下即可展示（液态 ODE + 时间尺度路由，非参数量堆叠）
- 训练成本可控：2B 原生训练 + 对齐可在 8×H100 级 2-4 周内完成

## 2. 架构规格（2B 目标）

| 组件 | 规格 | 依据 |
|---|---|---|
| d_model | 2048 | 与同规模 transformer 对齐，液态 ODE 需足够通道数 |
| n_layers | 16 | 深度对应皮层分层（5 层认知栈 × 3+ 子层） |
| 原丝数 | 13（保持 MT-LNN） | 已验证，微管仿生常数 |
| 时间尺度 | 16（τ 谱）| E3 扩容实验验证后定 |
| 路由 | top-k 门控（k=4）| L3 稀疏时间尺度路由，计算稀疏 |
| 工作记忆 | h_prev O(1) + 快权重 | L2，已验证 8063× @1M 上下文 |
| 记忆控制器 | selective_decay 学习型 | E4 A/B 决策 |
| 预测头 | k=3 步前瞻（MTP 液态版）| E2 验证 |
| vocab | 50257（gpt2）| 复用现有数据管线 |
| 序列 | 8192 训练 / 1M 推理（O(1) 内存）| 长上下文定位 |

**参数预算**（~2B）：
- 液态主干：16 层 × d_model 2048 × 13 原丝权重 ≈ 1.5B
- 快权重 / 记忆控制器 / 预测头 / 路由：≈ 0.3B
- 嵌入 + 输出头：≈ 0.15B
- 合计 ≈ 2B（INT4 部署 ~1GB）

## 3. 数据策略

| 阶段 | 数据 | 规模 | 目的 |
|---|---|---|---|
| P1 预训练 | WikiText-103（已有）+ SlimPajama/RedPajama 子集 + 代码（The Stack 子集）| 150-300B tokens | 液态主干语言能力 |
| P2 长上下文 | 拼接长文档 + 跨窗口续写 | 30-50B tokens | O(1) 工作记忆 + 快权重跨窗口绑定 |
| P3 多模态 | 视觉/音频流投影（对齐液态时间网格）| 10-20B tokens | 统一时间空间而非统一 token（Kimi 对照） |
| P4 对齐 | 指令 + GRPO 正确性奖励 | 1-5M prompts | 系统2 推理涌现 + 系统1/2 双轨 |

**数据管线注意**：
- 远程 GPU 网络受限 → hf-mirror + 本地 bin 转换（Spark1 已验证方案）
- tokenizer 复用 gpt2（50257），避免重训

## 4. 算力路径（四阶段）

| 阶段 | 规模 | 算力 | 耗时 | 决策点 |
|---|---|---|---|---|
| S0 已完成 | 125M 收敛 + selective_decay A/B | DGX Spark ×2（24h 租用）| 已跑 | 架构组件有效性（E4）|
| S1 进行中 | E1 液态 GRPO / E2 MTP / E3 尺度扩容 | DGX Spark ×2 | 1-2 天 | RL 是否涌现（E1 成败判据）|
| S2 缩放曲线 | 350M → 1B（3 个规模点）| 8×4090 / 4×H100 | 1-2 周 | scaling 曲线斜率：液态是否随规模有效提升 |
| S3 2B 正式 | 2B 预训练 → 长上下文 → 多模态 | 8×H100 / 2×DGX B200 | 2-4 周 | 能力基线 vs 同规模 transformer |
| S4 对齐 | GRPO + 系统1/2 蒸馏 | 8×H100 | 1 周 | 推理涌现 + 成本-能力曲线 |

**关键原则**：S2 的 350M/1B 点必须在 2B 之前跑——如果缩放曲线平缓（液态不随规模增益），2B 不值得投入。**S2 是 Go/No-Go 闸门**。

## 6. 风险与缓解

| 风险 | 概率 | 缓解 |
|---|---|---|
| 液态架构在 2B 规模不收敛/难训练 | 中 | S2 缩放曲线先行；必要时调优液态 ODE 数值稳定性 |
| GRPO 在液态上不涌现推理 | 中 | E1 先行；失败则回退到监督 + 稀疏奖励课程 |
| 2B 训练算力不足 | 高 | 明确租用预算；S2 数据先于 S3 决策 |
| 多模态数据管线复杂 | 中 | 复用 MT-LNN SensoryFrontend；先文本后多模态 |
| 远程 GPU 网络受限 | 高 | 本地中转 wheel/数据 + hf-mirror（已验证）|

## 8. 与现有实验的关系

| 实验 | 状态 | 对 2B 的贡献 |
|---|---|---|
| E1 液态 GRPO | 🔴 待跑（Spark2）| 决定 L5 对齐策略 |
| E2 MTP 前瞻 | 🟡 待跑 | 决定 L4 预测头规格 |
| E3 时间尺度扩容 | 🟡 待跑 | 决定 L3 路由规格（5→16）|
| E4 125M + seldec A/B | 🟢 进行中（Spark1）| 决定记忆控制器规格 |
| E5 多视野统一输出 | 🟡 设计完成（冒烟已过，待 GPU）| 决定 L4 视野规格（短↔长统一头）|
| E6 跨域零样本迁移 | 🟡 设计完成（冒烟已过，待 GPU）| 决定多域预训练 / 冷启策略 |
| E7 数据形态探针 | 🟡 设计完成（冒烟已过，零 GPU 可全量）| 决定 L1 数据形态（事件边界/Δt 通道）|
| E8 数据生成闭环 | 🟡 设计完成（脚本待 E7 结案）| 决定闭环组装是否优于散件 |

**2B 架构参数（d_model/层数/尺度数）全部由 E1-E6 的结果锁定，不在 S3 拍脑袋。**
**E5/E6（2026-09 新增）为 EnergyTS 对标实验**（长短时路径统一架构 / 零样本冷启）——
把"端侧液态栈 vs 云侧大基模"的能力边界问题变成可验证实验；不改变 S2 的 Go/No-Go 地位。
**E7/E8（2026-09-12 新增）为"数据源 = L1"定性实验**（ARCHITECTURE_C1 §0 原则 5）——
验证类脑机制在流式形态上是否有受力面（E7，零 GPU）+ 数据生成闭环是否优于散件（E8）。

## 9. 与 M3 的关系（2026-08-18 定性）

- **同一架构的两种表达**：三层记忆同构（C1 工作/情景/语义 ↔ M3 注意力/液态/
  fast-weight）、系统1/2 双轨 ≈ M3 的 DTD 动态深度、预测编码 surprise ≈ M3
  L3 门控信号源
- **分工**：C1 = 公开愿景版（纯液态激进变体，回答"液态能走多远"）；
  M3 = 私有证据版（混合 + 三轴，回答"如何逼近 Gemini 3 问答质量"）
- **实验合并**：C1 的 E1-E3 与 M3 的 A/B/C/S1/P1 互补不重叠，共用实验体系；
  E1-E3 的结果同时服务于 C1 路线图与 M3 的 scale-up 决策
- 任何一方文档与另一方冲突时，以 M3 的实测证据为准
